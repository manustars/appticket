The help desk is installed as {{ include "hd.fullname" . }} in namespace {{ .Release.Namespace }}.

{{- if .Values.ingress.enabled }}

Agents sign in at https://{{ .Values.ingress.host }}/
{{- else }}

Agents sign in through a port-forward (the sign-in cookie needs HTTPS or localhost):

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "hd.coreName" . }} 8080:{{ .Values.service.port }}
  then open http://localhost:8080/

First steps, with the `hd` command inside the core's pod (docs/deploy.md has the details):

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "hd.coreName" . }} -- hd customer add "<help desk>" --help-desk --domain <domain>
  kubectl -n {{ .Release.Namespace }} exec -it deploy/{{ include "hd.coreName" . }} -- hd agent add <agent e-mail> --name "<name>"

The first agent gets the Administrator role and can add the others under Administration.
{{- $databaseSource := include "hd.databaseSource" . }}
{{- if eq $databaseSource "cloudnativepg" }}

The database is the CloudNativePG cluster {{ include "hd.dbName" . }} (postgresql.mode=cloudnativepg); the core
verifies its certificate against the cluster's own authority.
{{- else if eq $databaseSource "standalone" }}
{{- $standalone := include "hd.standaloneName" . }}

The database is the chart's own PostgreSQL {{ $standalone }} (postgresql.mode=standalone), one instance
that the core reaches inside the cluster without TLS; the core's log says so at every start.
`helm uninstall` leaves its volume (the claim data-{{ $standalone }}-0) in place, and installing
again under the same release name takes it back.
{{- if .Values.postgresql.standalone.existingSecret }}
Its password is in the Secret {{ include "hd.standaloneSecret" . }}; PostgreSQL took it when it first created its data.
{{- else }}
Its password was generated into the Secret {{ $standalone }}, which upgrades keep and `helm uninstall`
leaves beside the volume. A tool that renders the chart without reading the cluster, such as
Argo CD, needs a Secret of your own instead: postgresql.standalone.existingSecret.
{{- end }}
{{- else }}

The database is an external one (postgresql.mode=external), given as {{ ternary "a Secret holding its URL" "separate values" (eq $databaseSource "external-url") }}.
The core verifies the certificate of a database on another host (verify-full) unless
core.database.sslMode{{ if eq $databaseSource "external-url" }} or the URL's sslmode{{ end }} says otherwise; a core that cannot verify it does not
start and logs why (docs/kubernetes.md, "TLS to the database").
{{- end }}

Upgrading from 0.3: the default postgresql.mode is standalone since 0.4.0. A release that runs
on the CloudNativePG cluster, the default until then, sets postgresql.mode=cloudnativepg from now
on. The chart refuses an install or an upgrade whose mode is not that of the database it finds
in the cluster, so that the core never starts on another, empty database. A tool that renders
the chart without reading the cluster, such as Argo CD, gets no such check:
set postgresql.mode explicitly there
(docs/kubernetes.md, "Upgrading from 0.3: standalone is the default database mode").
{{- if not .Values.assistant.enabled }}

To add the Assistant, register it first:

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "hd.coreName" . }} -- hd addon add assistant \
    --url http://{{ include "hd.assistantName" . }}:8090 \
    --event message.received --event ticket.opened \
    --scope directory:read --scope tickets:read --scope proposals:write

then put the printed token and event secret in a Secret and enable assistant.* in the values.
{{- end }}

To add the Zabbix add-on, register it first:

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "hd.coreName" . }} -- hd addon add zabbix \
    --url http://{{ include "hd.zabbixName" . }}:8091 \
    --scope directory:read --scope catalog:write --scope names:write --scope conflicts:write \
    --scope tickets:read --scope tickets:write --event ticket.state_changed

then put the printed token and event secret, the Zabbix user's API token and a webhook secret in
a Secret, write its configuration in zabbix.config and enable zabbix.* in the values.
{{- end }}

The dumps require TLS to the database but do not verify its certificate, which the core does: the
dumps' image holds no public certificate authorities. Give the database's authority in
